# Codex 宠物

独立插件 **`local.codex-pet`**，使用现有 PI-Desktop 插件接口提供 Codex 格式宠物、桌面浮窗、快捷聊天和会话活动面板。旧宠物插件已移除；本插件从头实现，不附带任何预设宠物素材，也不改动宿主接口或数据库。

这是在当前接口范围内的功能复刻。标准 v1 图集以公开 Codex 资料为依据；v2 布局、原版桌面交互细节和需要额外宿主能力的功能，分别标明兼容实现或下一阶段缺口，见 [PHASE-2.md](docs/PHASE-2.md)。

## 安装与打开

在应用插件页面导入 `dist/` 中的 `.piplug` 并启用。清单要求宿主版本 `>=2610.610.2408`，同时宿主须具备现有的 `desktop.getSessionSnapshot` 与 `pluginBridge.widget` 接口。仅安装插件不能为旧主程序补齐接口。

首次打开没有预设角色。在「宠物设置」导入已有 `pet.json` 和 PNG/WebP 图集，或选择现有图集新建宠物。菜单、插件视图和命令面板均可进入设置。

0.1.3 将控制栏收起为细条，悬停时展开，移开后延迟收起；输入时保持展开。快捷输入只保留同一行的输入框和发送按钮，支持粘贴/拖放图片与文件、图片缩略图和附件移除。宠物区域固定在视口顶部，聚焦输入不滚动页面，展开时按内容实际高度调整原生窗口。

快捷发送不再提供独立模型选择，后续消息复用宠物已关联的同一对话，模型、模式及思考档位沿用该对话；首次没有关联对话时使用宿主默认设置创建。当前 SDK 没有读取主窗口当前选中对话的接口，因此关联目标是宠物自身的对话。关联会话已删除或查询失败时报告错误并保留草稿。

0.1.2 修复内嵌设置页的启动识别：等宿主在 DOM 就绪时写入 placement 标记再加载应用；没有标记时仅探测一次原生窗口能力。工作面板中的设置页不启动浮窗位置、置顶或光标穿透轮询，原生窗口能力失效后停止后续相关调用。已在浏览器独立页面中模拟延迟标记、缺失标记、正常浮窗和运行中窗口能力失效四条路径；不将这些模拟结果当作安装版原生实机验收。

0.1.1 修复设置浮窗的关闭与弹层：右上角关闭按钮随滚动保持可见，Escape 先收起菜单、再次按下关闭设置浮窗；内嵌设置视图仍由宿主标签管理。导入和主菜单使用顶层弹层，贴边时限制在视口内并按空间向上或向下展开，不再被内容容器裁切。关闭设置窗口只关闭该窗口，不覆盖聊天草稿。

| 入口 | 行为 |
| --- | --- |
| `pet` 命令 | 显示或隐藏宠物 |
| `codex-pet.show` | 显示宠物并展开快捷输入 |
| `codex-pet.hide` | 隐藏宠物 |
| `codex-pet.settings` | 打开宠物设置 |
| 默认全局快捷键 | macOS 为 `Alt+Space`，其他平台为 `Super+Alt+P`；可在设置中录制、清除或修改 |

快捷键注册失败会保留原设置；冲突由宿主快捷键注册器判定。隐藏浮窗后可通过命令或快捷键再次显示，活动监测继续运行；停用插件会释放监测、订阅、命令与快捷键。

## 已实现能力

| 功能 | 当前行为 |
| --- | --- |
| 宠物库 | 目录导入、文件配对、拖放目录和文件、安装链接导入；批量导入中单个资源失败不会中断其余资源 |
| 新建、切换与移除 | 从已有图集生成元数据；选择宠物或「无」；同 ID 更新替换自有副本，移除仅删除插件副本 |
| 导出 | 下载 `pet.json` 和图集，保存到同一目录后可重新导入；下载导出将图集引用改为文件名，兼容原资源的嵌套路径 |
| 图集与动画 | Canvas 逐帧裁切，idle、左右移动、挥手、跳跃、失败、等待、工作与审阅动作；支持自定义 `frame` / `animations` |
| 桌面交互 | 拖动、保存位置、按方向键移动（Shift 精细移动）、Escape 重置位置、单击挥手、双击快捷输入、菜单挥手与跳跃 |
| 浮窗 | 置顶开关、32–256 DIP 大小、像素或平滑缩放、透明像素鼠标穿透、工作区位置裁剪、显示器移除后归位逻辑 |
| 减少动画 | 跟随系统、减少或完整；减少动画时显示 idle 首帧 |
| 活动 | 展示运行、等待审批/回答、完成和失败；简短工具摘要、待处理数量、排队数量、未读通知徽标、打开会话、单条或全部已读 |
| 快捷聊天 | 单行输入与发送，Enter 发送、Shift+Enter 换行、中文输入法保护，图片/文件粘贴与拖放；消息沿用宠物关联对话及其模型 |
| 草稿与失败恢复 | 文本与附件保存到插件数据目录；保留旧技能/模型字段的兼容读取，当前界面不提供独立选择；失败保留草稿与关联会话，按用户消息 ID 核对已接收消息，减少重试重复投递 |
| 外观 | 简体中文与 English、浅深主题、独立浮窗设置页及宿主内嵌设置视图 |

待审批/待回答数量与未读通知分开统计。标记已读只修改宿主持久化通知，不代表完成审批，也不会删除任务记录。活动失败时保留已有摘要并提示过期状态。

附件读取完成前不能发送。插件菜单主动隐藏前会等待正在读取/发送的操作与草稿保存；输入变化立即排队保存。系统强制退出或原生关闭不具备可靠的关闭前回执接口，极短时间内尚未完成的写入仍不能保证，详见下一阶段文档。

## Codex 文件兼容

标准 v1 目录可以直接导入，例如：

```text
my-pet/
  pet.json
  spritesheet.png
```

```json
{
  "id": "my-pet",
  "displayName": "我的宠物",
  "description": "自己的素材",
  "spritesheetPath": "spritesheet.png",
  "spriteVersionNumber": 1
}
```

- v1 标准图集为 **1536×1872**，8 列、9 行，每帧 **192×208**；PNG 和 WebP 均可使用。
- `id`、`displayName`、`description` 与版本可省略；未提供版本时使用 v1，未提供图集路径时使用 `spritesheet.webp`。插件为缺少 ID 的导入资源补充本地标识。
- 导入保留额外 manifest 字段；支持 Codex 公开模型中的自定义帧尺寸、列行数、动作帧列表、fps、loop 与 fallback。
- PNG 验证包括文件结构、CRC 与解压完整性；WebP 在后端读取容器与尺寸，在页面中实际解码。损坏图片会提示错误，不应把 WebP 头部通过视为完整解码验证。
- v2 当前接受 **1536×2288 / 8×11** 兼容布局和后两行的 16 方向注视映射；这些细节尚未得到公开原版桌面播放器或真实资源验证，不能视为原版 v2 的完整规格。默认新建使用已确认的 v1。

`codex://pets/install` 链接可粘贴到设置页导入，支持 `name`、`imageUrl`、`description` 与 `spriteVersionNumber`。只在用户点击导入时下载指定 HTTPS 图集；插件不注册系统 `codex://` 协议，也不覆盖 Codex 的关联。

## 状态与数据边界

插件仅访问宿主已有会话接口，不读取 Codex 的聊天数据库，也不自动写入或扫描 Codex 的原始宠物库。导入资源复制到 `pi.plugin.getDataPath()` 返回目录下的 `pets/`；草稿保存为 `chat-draft.json`，设置由宿主插件设置保存。附件写入所属新会话的 scratch 目录。

活动订阅最多 16 个会话，总请求并发最多 4 个。全部宿主会话公平轮转轻量状态探测，每轮最多 16 个；发现活动后读取快照和订阅，超额活动继续轮换纠偏。若有 N 个会话，首次发现的等待可能达到 `ceil(N/16) × 刷新间隔 + 请求耗时`。已订阅会话通过事件更新，周期快照兜底。不存在“所有会话立即推送”的保证。

联网权限用于任意 HTTPS 安装链接。当前 SDK 的 `net.fetch` 只提供文本响应，因此二进制图集下载使用插件 Node fetch；静态检查会报告权限提示和 `net.fetch` 未直接调用提示。这不是检查失败。无需配置其他后台服务。

## 构建与验证

先准备仓库已有工作区依赖，然后执行：

```bash
npm --prefix plugins/codex-pet run test
npm --prefix plugins/codex-pet run check
npm --prefix plugins/codex-pet run pack
```

`check` 只编译与检查本插件；`pack` 在成功检查后生成 `dist/*.piplug`，文件名包含版本与内容摘要，成功后只保留最新插件包，失败时保留上一份。构建中间文件使用会话 scratch 或系统临时目录，不生成主程序安装包，不修改主程序版本。

本次验证覆盖插件 Node 测试、前端语法、插件 devkit 静态检查，以及实际浏览器中的设置页、快捷输入、通知控件、图集裁切、alpha 命中与减少动画。浏览器联调使用临时合成图集及明确的模拟宿主回包，测试素材不随包分发。

未执行主程序全量测试或构建，也未启动后端服务。未把浏览器结果当作 Electron 原生浮窗、多屏缩放、操作系统穿透、安装后真实模型请求或 Codex 原版视觉对照的验收结果。
