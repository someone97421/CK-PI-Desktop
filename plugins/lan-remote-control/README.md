# 局域网远程控制插件

手机与 Chrome 侧栏现在直接运行宿主编译后的 `apps/desktop/src` Renderer，使用同一套聊天组件、状态管理和业务 IPC。需要同时更新宿主与插件；构建、协议测试与真实手机/扩展验收分别记录，不把打包成功等同于实机通过。

网络监听、密码认证、设备管理、资源代理和 Browse 浏览器调试由本插件提供；模型、工具、队列和业务数据由桌面宿主处理。

## 源码与安装产物

源码位于本目录，并已加入 pnpm 工作区以供桌面内置构建使用；也可单独生成插件包：

```bash
npm --prefix plugins/lan-remote-control ci --ignore-scripts
npm --prefix plugins/lan-remote-control run check
npm --prefix plugins/lan-remote-control run pack
```

`check` 只编译该插件的入口与网页，并使用仓库现有 plugin-devkit 检查 manifest/资源，不启动服务或运行测试。`pack` 使用同一 devkit 生成 store-only `.piplug`，位于本目录 `dist/`，当前源码对应的插件包随源码一起提交推送。打包成功后自动删除 `dist/` 中的历史插件包。每次编译生成独立 `.build/plugin-*` 目录，成功后删除旧构建目录，只保留最新一份及共用工具；构建失败时保留上一份成功产物。这些构建目录和依赖不进入 Git。

本插件随桌面应用内置，首次登记缺省关闭，已有启停选择与设置继续保留。也可在插件管理页安装 `.piplug` 更新。开发目录加载应指向命令输出的 `.build/plugin-*`，不要直接加载包含未打包浏览器依赖的源码目录。

当前随仓库提供的安装包位于 [dist/](./dist/)，只保留最近一次成功打包的版本。

插件版本独立于宿主日期版本。manifest 中的最低版本只是基础门槛；完整流式订阅等能力依赖本分支新增的受控宿主 API。旧版或上游原版是否兼容由运行时能力探测决定，不能仅凭版本号推断。

每次执行 `npm --prefix plugins/lan-remote-control run pack` 自动递增插件补丁版本（例如 `0.2.0 → 0.2.1`），产物生成成功后同步 `manifest.json`、`package.json` 和 `package-lock.json`。普通 `build` / `check` 不改变版本；编译或检查失败不递增版本。

插件源码与最新 `.piplug` 应一起提交；桌面构建通过 `scripts/prepare-builtin-plugins.mjs` 从源码生成内置资源。

## 使用

1. 在桌面插件管理页启用“局域网远程控制”；已有插件设置和认证数据继续沿用。
2. 点击侧栏底部的远程入口，打开“局域网远程控制”面板。
3. 在电脑设置访问密码和端口（默认 `7878`），开启远程访问。插件逐个监听当前所有本机局域网 IPv4 地址（包括符合私网范围的虚拟网卡），额外监听 `127.0.0.1`；全部入口使用同一端口，无局域网时本机入口仍可启动。
4. 面板列出监听成功的访问链接，可分别复制。手机打开可达链接并输入主机密码登录；各入口共用密码、设备记录和访问限制。浏览器按服务端地址保存登录状态，换一个链接可能需要重新登录。
5. 电脑面板记录已登录设备、在线状态、地址与最近访问时间，可移除单台或全部设备。

Chrome 侧边栏连接 `http://127.0.0.1:7878`，使用同一密码和设备记录。固定扩展 ID `afeafocngkodbmaipcngoamamfmekgfo` 始终受信任；其他安装方式可在面板添加自定义扩展 ID（32 位 `a-p` 小写字母），保存后立即应用于 HTTP/CORS 与 WebSocket，不改变 LAN 监听范围。

面板提供 Browse Relay 状态、启动和一次性配对码。需安装支持 `pair --mint-json` 的 `browse`，可执行文件从 `PATH` 或 `~/.local/bin/browse` 查找；Relay 固定为 `http://127.0.0.1:19988`。插件声明 stdio MCP `browse mcp`，环境为 `OPENCODE_BROWSER_TOOLS=all`、`OPENCODE_BROWSER_PORT=19988`。未安装 CLI 时远控聊天仍可使用，Browse 操作明确报告不可用。密码登录后的侧边栏可通过认证 RPC 获取配对码；跨机 Browse 连接仍取决于 Relay 自身能力。

手机和侧栏采用三级导航：项目大厅 → 原版对话 → 全屏 WorkPanel。大厅固定置顶临时会话，各项目普通会话首屏显示 3 条，每次加载更多追加 5 条，折叠重置；支持搜索、刷新和新建。临时会话可填写电脑上已有的绝对工作目录，留空使用会话临时目录，不登记为项目。首次发送才创建正式会话，附件先按草稿身份导入。

二级界面复用原版 `ConversationTopbar`、`ChatSurface` 与 Composer，包括消息过程、修改卡、TodoDock、TaskDock、技能命令、文件引用、模型、思考、模式与权限选择。窄屏菜单限制在视口内。文件选择使用浏览器上传，粘贴附件通过 IPC 还原字节后交给宿主导入；新 Renderer 上传支持源码等通用文件，沿用大小和设备配额限制。

文件审查、文件树、子代理观测和侧边对话在第三级全屏推入，顶部“返回对话”及浏览器返回键退出；二级顶部“返回项目列表”回到大厅。宽屏 Electron 布局沿用原行为。Web 文件树使用现有 React FilesTab，其他需要原生 WebContentsView 的插件页面显示能力提示。

Chrome 侧栏顶部保留 Browse 状态、借出当前页、`@当前页` 和 Handoff。下方 iframe 加载同一 Renderer；来源与窗口均校验，认证令牌只留在 iframe。登录后尝试配对 Browse，`@当前页` 向当前可编辑会话插入浏览器上下文。

Web 桥本地处理窗口布局、原生菜单、通知等展示调用，避免改变电脑窗口；普通外链在当前浏览器打开，需要电脑原生窗口的操作明确返回不支持。业务事件仍实时同步。可视化、插件资源和外观媒体通过已认证的资源代理复用 Electron 协议读取器。

设备登录有效期为 30 天。关闭服务、禁用插件或退出应用会立即断开连接，保留设备记录；重新开启（含自动恢复）后可继续登录。改密或移除设备使令牌失效，需要重新输入密码。

远程访问关闭不会终止已经被宿主接收的智能体任务，也不会删除会话。电脑需要保持运行且网络可达；防火墙、访客 Wi-Fi 或设备隔离可能阻止访问。插件不自动修改这些系统设置。

## 开启状态与凭据的持久化

面板上的“开启/关闭”不只是本次会话的开关：

- 在面板点击“开启”会保存端口和开启意图；主程序关闭后重开、插件重新启用时，会按保存的端口重新枚举并监听全部本机私网地址，直到你在面板点击“关闭”。旧设置中的 `bindAddress` 字段继续兼容读取，仅作为首选链接，不限制监听范围，也不因旧地址已失效而阻止恢复。
- 应用退出、插件停用（宿主发起的服务停止）或插件重新加载都不算用户手动关闭：它们只断开当前连接、停掉监听，不会清除开启意图。
- 可恢复的故障（端口被占用、监听套接字意外关闭等）不会撤销开启意图：插件按指数退避持续重试，间隔 3→6→12→24→48 秒，最多 60 秒一次，不设次数上限。面板显示“正在自动重试开启”或上次失败原因，可随时点击“开启”立即重试，点击“关闭”彻底停止。
- 靠重试解决不了的问题（还没设访问密码、地址/端口不合法、系统拒绝监听等）改为每 5 分钟低频复查一次，并在设置变化后立刻复查；设好密码会立即重试一次。意图始终保留，不会因为一直失败而放弃。
- 插件每 30 秒检查待保存设置与服务状态：无论开关状态如何都会补写失败的设置；意图开启且未卸载时，发现监听意外停止就重新枚举所有本机私网地址并恢复。正常运行时不自动重绑；网卡地址集合或设置端口变化后，面板提示重新开启。
- 自动恢复和面板开启走同一条路径：逐个绑定枚举得到的本机私网 IPv4 地址及 `127.0.0.1`，端口仍须是 1..65535 的整数，监听后再次核对实际地址；不会绑定 `0.0.0.0`、`::` 或公网地址。密码、设备令牌与登录限制保持共享。
- 某个地址绑定失败时，其余成功入口继续工作，面板持续显示失败地址和原因；再次开启可重试。全部失败才进入原有自动重试流程。关闭服务会停止全部 HTTP 监听、WebSocket 和订阅；改变端口或重新开启以应用网络变化，会断开已有连接。
- 凭据不落明文：访问密码以随机盐 scrypt 校验值保存在插件数据目录的 `remote-access.json`，设备令牌只存 SHA-256；旧地址字段、端口和开启意图继续保存在原有插件设置记录 `settings.json`，无需迁移。数据目录只认宿主返回的插件数据目录，读不到时明确报错并保持现有数据。设置写入失败会在面板提示“未能保存”，并在存活检查/设置变化时补写。
- 已知限制：插件宿主进程自身崩溃时，能否自动重启插件由宿主按 manifest 中该服务的 `autoRestart` 决定；重启后插件再按开启意图恢复监听，在此之前不提供访问。绑定成功不代表防火墙或手机所在网络允许连接。

## 权限与安全

- `desktop.control`：密码认证后通过 `/api/ipc` 调用宿主 `IPC_WHITELIST` 中的注册处理器；新增桥接口仅允许 `local.lan-remote-control` 使用，不触发电脑二次确认。
- `models.list`：读取可用模型，不读取模型凭据。
- `ui.panel`、`background.service`：桌面管理界面与插件生命周期。
- `mcp.server.local`：向宿主提供 Browse stdio MCP 声明；`check` 和 `pack` 均核对 MCP transport 与本地/远程权限匹配。
- `clipboard.write`：从可信桌面面板复制访问链接。
- 网络监听使用插件独立 Node 进程。现有 SDK 没有网络监听权限项，因此安装授权清单不能独立描述监听能力；只有本地面板明确“开启”过（或该意图仍被保存）才会监听端口，默认不监听。自动恢复开启不是绕过：它复用保存的用户意图与同一套校验。
- 服务逐个绑定本机私网地址及回环；访问链接不含密码或设备令牌。密码使用随机盐 scrypt 校验，设备令牌服务端只存 SHA-256；所有入口共用登录请求频率和并发限制。认证文件 `remote-access.json` 保存在插件自己的数据目录，设置仍由宿主插件设置 API 持久保存；沿用已有认证格式，无需迁移业务数据库。
- 普通 HTTP/WS 没有传输加密，仅用于可信局域网，不适合公网暴露。知道地址不等于获得访问权限。
- 手机密码登录后可直接修改模型、思考级别、工作模式和权限模式，处理工具审批、智能体提问、历史 Plan/Goal 审批及新模式运行控制和阶段审批。宿主直接执行手机提交的操作。此行为需要同时更新主程序和插件，仅更新插件无法改变旧主程序的处理方式。
- 上传只写插件自己创建的暂存区域，通过受控导入交给宿主；不直接修改数据库或转录。临时工作目录只在新建时指定，由宿主沿现有临时会话流程校验和绑定。

## 协议与实现说明

- [宿主操作协议](./PROTOCOL.md)：操作白名单、参数和能力信息。
- [网络与面板协议](./SERVER-PROTOCOL.md)：密码登录、RPC、WebSocket、附件及生命周期。
- [实施计划](../../docs/LAN-REMOTE-CONTROL-PLAN.md)：两阶段范围和验收要求。

面板接口 `remote.status` / `remote.refresh` 的状态新增 `links: [{ address, label, url }]`，仅包含成功监听的入口；停止时为空数组。原有 `address`、`bindAddress` 和 `url` 保留为首个成功入口，`addresses` 仍是本机候选地址。`remote.link` 同时返回 `links` 和兼容字段 `url`。部分失败通过 `warning: { code: "PARTIAL_LISTEN_FAILED", message, failures }` 返回，`failures` 包含失败地址、网卡名称与错误原因；网络或端口变化使用 `restartRequired` 提示重新开启。

旧 `/api/rpc` 保留原请求结果查询语义。新 `/api/ipc` 原样传递宿主 `Result`，网络失败不自动重放写操作；断线重连后刷新业务快照。

## 验证范围

代码检查、打包检查、安装验证和真实手机连接是不同的验收项。实际执行记录随本轮实现审查更新；本文件不把安装或实机验证预先写为通过。

`npm --prefix plugins/lan-remote-control run test:settings` 使用 Node 内置测试运行器，对真实设置模块做隔离回归（模拟宿主与最小 DOM），不启动服务或修改用户数据。它覆盖排队回执、重复编辑、撤回待生效值、取消、重复点击和失败重试，不代替宿主或实机联调。

`npm --prefix plugins/lan-remote-control test` 运行连接器、IPC/事件流、Renderer 静态资源/CSP、上传与资源代理、原模型设置及临时会话测试。网络测试使用隔离密码和临时数据，不读写实际用户凭据。`scripts/check-auth.mjs` 与 `scripts/check-regressions.mjs` 继续提供旧认证和聊天恢复回归。
