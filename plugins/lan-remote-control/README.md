# 局域网远程控制插件

**当前为未完成验收的开发版本。** 0.2.0 已完成插件构建与打包，尚未进行安装和实机验收；手机独立审批、跨端侧边对话关联等仍有明确缺口，见 [实施审查记录](./IMPLEMENTATION-STATUS.md)。不要将本安装包视为两阶段已全部完成。

为“这是一个助手”提供可启停的局域网浏览器入口。网络服务、密码认证、设备管理和移动网页都在插件内；模型、工具、队列和业务数据仍由桌面宿主处理。

## 源码与安装产物

源码位于本目录。开发依赖独立管理，不要求修改桌面工作区依赖：

```bash
npm --prefix plugins/lan-remote-control ci --ignore-scripts
npm --prefix plugins/lan-remote-control run check
npm --prefix plugins/lan-remote-control run pack
```

`check` 只编译该插件的入口与网页，并使用仓库现有 plugin-devkit 检查 manifest/资源，不启动服务或运行测试。`pack` 使用同一 devkit 生成 store-only `.piplug`，位于本目录 `dist/`，当前源码对应的插件包随源码一起提交推送。打包成功后自动删除 `dist/` 中的历史插件包。每次编译生成独立 `.build/plugin-*` 目录，成功后删除旧构建目录，只保留最新一份及共用工具；构建失败时保留上一份成功产物。这些构建目录和依赖不进入 Git。

从桌面插件管理页安装 `.piplug`。开发目录加载应指向命令输出的 `.build/plugin-*`，不要直接加载包含未打包浏览器依赖的源码目录。

当前随仓库提供的安装包位于 [dist/](./dist/)，只保留最近一次成功打包的版本。

插件版本独立于宿主日期版本。manifest 中的最低版本只是基础门槛；完整流式订阅等能力依赖本分支新增的受控宿主 API。旧版或上游原版是否兼容由运行时能力探测决定，不能仅凭版本号推断。

每次执行 `npm --prefix plugins/lan-remote-control run pack` 自动递增插件补丁版本（例如 `0.2.0 → 0.2.1`），产物生成成功后同步 `manifest.json`、`package.json` 和 `package-lock.json`。普通 `build` / `check` 不改变版本；编译或检查失败不递增版本。

## 使用

1. 在插件管理页安装并授予声明的权限。
2. 点击侧栏底部通知铃铛右侧的远程入口，打开“局域网远程控制”面板。入口需要本分支新版宿主与 0.2.0 插件配合；旧宿主仍可从插件管理页打开面板。
3. 在电脑设置访问密码，选择本机局域网地址和端口，开启远程访问。地址和端口会保存为下次的默认值；“自动选择本机私网地址”表示由插件挑选当前可用的私网地址。
4. 生成并复制访问链接，手机打开后输入设备名和密码即可登录。
5. 电脑面板记录已登录设备、在线状态、地址与最近访问时间，可移除单台或全部设备。

侧栏绿点表示监听已开启，红点表示关闭或状态不可用，悬停可查看状态。手机首页的项目卡片支持展开对话、搜索筛选、刷新及新建；点选进入独立会话页，顶部返回按钮或手机返回键回到首页。每条消息的操作收在“更多”菜单里，手机工具栏采用 SVG 图标。

会话按任务折叠工作过程，最终回复保留在外；点击“已工作…”可展开中间回复、思考和工具，任务提供统计时显示耗时与 token。旧记录缺少任务统计时只显示“工作过程”，不推算耗时。顶部可统一展开或收起过程。

点击顶部“子代理观测”或 Task 工具里的观测按钮，可查看子代理任务、状态和实时消息/工具时间线，并切换不同子代理。手机以覆盖面板展示，关闭后返回原对话；浏览较早过程时不强制跳到底部。观测内容来自当前已加载的会话记录，更早任务可先在主对话中加载更早消息。

主代理发送给子代理的引导会在观测时间线中显示为“主代理 → 子代理”消息框，同一指令随回执更新接收、应用中、已应用、取消或拒绝状态，并显示接收/应用时间及执行轮次。接收不代表已生效；正在执行的工具会先完成。当前轮即时引导机制需要配套的新版桌面运行时，单独升级插件只更新展示。

设备登录有效期为 30 天。关闭服务、禁用插件或退出应用会立即断开连接，保留设备记录；重新开启（含自动恢复）后可继续登录。改密或移除设备使令牌失效，需要重新输入密码。

远程访问关闭不会终止已经被宿主接收的智能体任务，也不会删除会话。电脑需要保持运行且网络可达；防火墙、访客 Wi-Fi 或设备隔离可能阻止访问。插件不自动修改这些系统设置。

## 开启状态与凭据的持久化

面板上的“开启/关闭”不只是本次会话的开关：

- 在面板点击“开启”会同时保存监听地址、端口和开启意图；主程序关闭后重开、插件被重新启用时，插件会按保存的地址和端口自动恢复监听，直到你在面板点击“关闭”。
- 应用退出、插件停用（宿主发起的服务停止）或插件重新加载都不算用户手动关闭：它们只断开当前连接、停掉监听，不会清除开启意图。
- 可恢复的故障（端口被占用、暂时没有可用私网地址、监听套接字意外关闭等）不会撤销开启意图：插件按指数退避持续重试，间隔 3→6→12→24→48 秒，最多 60 秒一次，不设次数上限。面板显示“正在自动重试开启”或上次失败原因，可随时点击“开启”立即重试，点击“关闭”彻底停止。
- 靠重试解决不了的问题（还没设访问密码、地址/端口不合法、系统拒绝监听等）改为每 5 分钟低频复查一次，并在设置变化后立刻复查；设好密码会立即重试一次。意图始终保留，不会因为一直失败而放弃。
- 插件每 30 秒检查待保存设置与服务状态：无论开关状态如何都会补写失败的设置；意图开启且未卸载时，发现监听意外停止就按保存的地址和端口恢复。服务正常运行时不会重新监听，也不会显示“正在重试”。
- 自动恢复和面板开启走同一条路径：地址仍须是本机私网/回环 IPv4 地址、端口仍须是 1..65535 的整数，监听后仍会校验绑定地址，密码、设备令牌与登录限制一律不变。插件不会为了让服务起来而放宽任何校验。
- 凭据不落明文：访问密码以随机盐 scrypt 校验值保存在插件数据目录的 `remote-access.json`，设备令牌只存 SHA-256；地址、端口和开启意图保存在插件设置记录 `settings.json`。数据目录只认宿主返回的插件数据目录，读不到时明确报错并保持现有数据，不退回临时目录或按路径哈希新建存储。设置写入失败会在面板提示“未能保存”，并在存活检查/设置变化时补写，不会谎报已记住。
- 已知限制：插件宿主进程自身崩溃时，能否自动重启插件由宿主按 manifest 中该服务的 `autoRestart` 决定；重启后插件再按开启意图恢复监听，在此之前不提供访问。防火墙、网络环境变化导致的地址失效仍会持续重试但无法自愈。

## 权限与安全

- `desktop.control`：通过现有宿主网关访问明确允许的项目和会话操作；浏览器不能传入任意宿主操作名称。
- `models.list`：读取可用模型，不读取模型凭据。
- `ui.panel`、`background.service`：桌面管理界面与插件生命周期。
- `clipboard.write`：从可信桌面面板复制访问链接。
- 网络监听使用插件独立 Node 进程。现有 SDK 没有网络监听权限项，因此安装授权清单不能独立描述监听能力；只有本地面板明确“开启”过（或该意图仍被保存）才会监听端口，默认不监听。自动恢复开启不是绕过：它复用保存的用户意图与同一套校验。
- 服务仅绑定选定的本机私网地址；访问链接不含密码或设备令牌。密码使用随机盐 scrypt 校验，设备令牌服务端只存 SHA-256；登录有请求频率和并发限制。认证文件 `remote-access.json` 保存在插件自己的数据目录，地址、端口和开启意图由宿主插件设置 API 持久保存；沿用已有认证格式，无需迁移业务数据库。
- 普通 HTTP/WS 没有传输加密，仅用于可信局域网，不适合公网暴露。知道地址不等于获得访问权限。
- 模型配置、工具审批、智能体提问等危险操作保留宿主原生确认。手机发起请求后如果桌面弹出确认，需要在桌面完成；插件不会自动批准或降低权限。完整的“手机独立审批”不能据此宣称已经实现。
- 上传只写插件自己创建的暂存区域，通过受控导入交给宿主；不直接修改数据库或转录。禁止任意本地路径输入。
