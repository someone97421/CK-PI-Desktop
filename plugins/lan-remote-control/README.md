# 局域网远控 V2

V2 直接托管当前主程序安装目录中的 `out/renderer`。聊天、侧栏、设置与工作面板使用同一套 Renderer 组件；插件包不包含独立聊天页面、消息渲染器或业务协议。

插件负责远控监听、账号密码与设备会话、自动开启状态、IPC／附件／资源网络转换，以及 `adapter/` 中的投影布局和导航。插件启用时默认监听 `127.0.0.1`。开启远控后监听 `0.0.0.0`，覆盖本机所有 IPv4 网卡。关闭远控会恢复本机监听，停用插件或退出应用会关闭全部监听。

V1（最后版本 `0.2.41`）已停止维护，源码快照和原始插件包见 [V1 归档](../../docs/archive/lan-remote-control-v1/README.md)。后续只维护 V2。

## 使用

在插件设置中保存访问账号和密码。旧配置继续使用原密码，默认账号为 `admin`。

浏览器侧栏与远控网页共用登录表单。首次访问时输入同一套账号和密码，后续使用各自保存的登录会话。Browse CLI 与 MCP 由主程序托管。

远控网页默认使用 `7878` 端口。外网通过 HTTPS 反代时，将网页、API 及 `/ws` 转发到插件端口。Host、Origin 和扩展 ID 无需登记。

远控网页与侧边栏共用三级覆盖布局：一级项目和会话列表，二级原版聊天工作区，三级全屏工作面板。选择或新建会话进入二级，原有右面板入口打开三级；返回按钮、浏览器历史和 Escape 支持逐层返回。原组件保持挂载，聊天草稿与面板状态随层切换保留。

Chrome 侧栏嵌入时，`adapter/browser-grip.js` 在原输入工具栏“添加文件”旁插入同样式的准星按钮；独立远控网页与桌面端不显示。按钮通过经过来源校验的 iframe 消息将原生拖动交给浏览器扩展；拖动时使用透明占位图隐藏图标拖影，网页只显示 DOM 边界，松手生成原有元素 chip，确认插入后在输入区播放轻量动画。没有扩展外层悬浮抓手，也不再使用修饰键点击或修饰键设置。

账号、密码哈希、设备记录和远控设置保存于 `local.lan-remote-control` 的插件数据目录。更换账号密码会让网页和侧栏重新登录，移除设备会撤销对应会话。`autoStart` 保存远控开启意图。

页面资源、已登录的 IPC／Browse RPC、上传与 WebSocket 消息不按每分钟请求数限流，避免页面加载和状态同步挤占消息发送。远程重连会合并补刷会话状态，请求期间的实时开始／结束状态优先于旧快照；旁路配置刷新失败不阻断会话恢复。发送失败保留草稿，不自动重放消息写入。

## 文件链接菜单与调用链

远控网页和 Chrome 侧栏的文件链接右键菜单，前两项固定为“预览”“下载”，由插件 `adapter/file-actions.js` 和 `file-actions.css` 独立维护。主程序 `FileReference` 只提供扩展动作入口；桌面端继续使用现有菜单。

1. `FileReference` 清理引用中的 `@`、URI 编码和行列后缀，以引用所属会话调用 `fsResolveRef`。文档相对链接先基于文档目录转换；项目／worktree、会话 scratch、附件与精确绝对路径由主程序现有解析器处理。
2. 插件动作捕获解析后的绝对路径和会话 ID，调用 Web 桥 `__piDesktopReadRemoteFile`，以当前设备登录凭据 POST `/api/file`。
3. 插件通过 `desktop.readRendererFile` 请求主程序。主程序检查会话来源，再以同一会话重新解析文件，打开普通文件并读取完整字节，不复用有大小／类型限制的 `fsRead` 预览结果。
4. 插件恢复二进制响应，返回 MIME、原始文件名与预览资源地址。浏览器得到 Blob；“下载”通过 `a.download` 保存原始字节，“预览”在当前网页内展示文本、图片、PDF、音视频或 HTML。未知二进制和不支持的文本编码提示下载，不按文本强行展示。
5. HTML 使用 `/api/file-view/<设备凭据>/<会话>/<平台>/<完整路径>` 加载，保留目录层级；相对 CSS、脚本和图片继续经主程序读取。预览文档使用 sandbox，资源响应允许其不透明来源读取。关闭、取消或替换预览会清理媒体及临时 Blob URL；下载 URL 延迟回收。

以上接口每次交付前重新检查设备登录状态。文件消失、目录误选、读取失败和登录失效会回传明确错误。SSH 远程工作区协议尚无完整二进制读取，本入口明确返回不支持，避免误读同名本机文件；此限制不影响通过局域网访问主程序本地工作区。

“使用默认程序打开”“在文件夹中显示”和电脑原生选择／配置操作，经 `/api/ipc` 交给主程序现有处理器执行并返回结果。窗口尺寸、可见性及原生视图几何仍由远端页面本地处理，避免改变主程序窗口。

## 工作面板插件视图

远控工作面板可在隔离的 iframe 中加载宿主允许的插件视图。父页面携带设备凭据调用 `POST /api/plugin-view/open`，提交 `pluginId`、`viewId` 与 `sessionId`，收到 `{ ok: true, result: { id, url } }`。视图资源保留完整的相对路径，资源 URL 与 iframe 内的桥只携带该实例的随机凭证。宿主应支持 `pi-desktop/remotePluginView` 的 `open`、`asset` 和 `invoke` 操作。

桥在插件脚本执行前提供 `invoke`、同步接收回执 `send`、`on`／`off` 以及宿主声明的能力。页面加载完成后向父页面发送 ready 消息。父页面通过 `postMessage` 转发匹配视图的宿主事件。浏览器无法取得主机的原生拖入路径，也不提供原生小组件窗口操作。

父页面卸载视图时携带设备凭据调用 `POST /api/plugin-view/close`，提交 `{ id }`。设备撤销、登录过期、服务停止或视图闲置六小时后，实例凭证失效。一个已登录设备最多可同时持有 32 个视图实例。

## 边界

- V1 的 `web/`、`panel/`、独立聊天适配器、消息/模型/模式操作表及旧页面测试已删除。没有 V1 页面回退路径。
- `settings/` 是重新编写的连接与密码管理入口；密码输入 Gate 位于主程序转换层。两处都不承载聊天界面。
- Renderer 缺失或宿主不支持转换接口时返回明确错误，不能仅靠安装插件让旧主程序获得 V2。
- `adapter/` 维护投影布局、导航和远端文件菜单；主程序提供状态事件、菜单扩展入口和文件读取服务，桌面布局不受影响。尚未完成真实手机、Chrome 与安装版全流程验收。
- V1 自定义聊天 RPC 已退出；项目、会话、审批、模型及模式操作统一走主程序现有 IPC。保留的 `/api/rpc` 仅用于已声明的 Browse 转换操作。

## 开发检查

只检查源码语法和相对导入时运行 `node plugins/lan-remote-control/scripts/check-source.mjs`。

```sh
npm --prefix plugins/lan-remote-control test
npm --prefix plugins/lan-remote-control run check
npm --prefix plugins/lan-remote-control run pack
```

打包携带插件服务、认证设置与投影适配资源，不复制 Renderer。成功生成新包后仅保留最新插件产物。

主程序构建入口 `scripts/build.mjs` 从 `scripts/builtin-browse-source.json` 固定的个人仓库提交编译对应平台 Browse，并将二进制、MIT 许可与来源校验信息放入应用资源目录。所有编译中间文件使用 scratch；源码版本、平台和校验值相符时复用现有资源。插件包不包含平台二进制。
