- 代码核对基线：`81ee7ebc`。
- 配套文档：[实现方案](./SUBAGENT-COLLABORATION-IMPLEMENTATION.md)。

## 1. 目标与现有问题

增强主 Agent 对子 Agent 的过程感知、纠偏能力，以及用户对单个子 Agent 的终止能力。主 Agent 和子 Agent 保持独立执行，子 Agent 不因例行汇报等待主 Agent 审批。

当前已有 `Task`、`TaskWait`、`TaskList`、`TaskStop`，以及子 Agent 工具调用事件和界面记录。但主 Agent 主要接收运行状态、调用次数和最终报告，尚未形成定期过程汇报与中途引导的完整机制；子 Agent 详情页也缺少独立人工终止入口。

本轮采用：**持续并行执行、程序自动汇报、主 Agent 按需引导、工具边界应用引导并自动继续、支持单独终止。**

## 2. 术语和计数

| 名称 | 含义 |
| --- | --- |
| 派发 | 主 Agent 使用 `Task` 启动一个具有独立 ID 的子任务 |
| 一步 | 一次实际发起的工具调用；同一调用的流式输出、状态更新不重复计步 |
| 汇报间隔 N | 每累计 N 个已结束的工具调用，由程序生成一次阶段汇报 |
| 引导 | 主 Agent 为正在运行的子任务补充或纠正指令，不新建子任务 |
| 本段 | 从首次派发或最近一次引导生效开始的一段执行过程 |
| 终止 | 禁止后续动作，取消可取消的在途操作，结束该子任务 |

计数规则：

1. 工具调用进入执行时登记步骤，结束时计入汇报间隔，确保汇报包含实际结果。
2. 已实际发起但失败的工具调用也计步；再次实际调用算新的一步。
3. 同一个工具调用 ID 的重复事件只记录一次；输出分块、模型文字输出不计步。
4. 因引导或终止而未真正执行的工具调用不计步，但记录其被跳过的原因。
5. 一次 Bash 工具调用算一步，不拆解其脚本内部命令数量。

## 3. 汇报是后台行为

程序从已有事件中收集执行记录，在满足 N 的条件时截取本批记录，形成报告并投递给主 Agent。此过程不暂停子 Agent，不要求子 Agent 额外写一次报告，也不向其上下文插入例行汇报通知。

报告包含：

- 子任务 ID、报告序号、本段编号、覆盖的步骤范围和时间。
- 本批进展摘要、错误或阻碍，以及已有输出中能确认的后续意图。
- 工具调用清单、经脱敏的关键参数、结果摘要、执行状态、耗时和相关文件引用。
- 完整记录的定位信息，以及摘要是否截断、是否存在尚未结束的操作。

执行记录由运行时生成，不能依赖子 Agent 自述。摘要必须区分事实、引用的 Agent 陈述和不确定项；不能凭工具名称推断操作已成功，也不能把可见的计划当成已经完成的工作。

主 Agent 默认接收本批增量和简明摘要，需要时再查完整记录。不得每次重复发送全部历史日志。若使用额外模型做语义摘要，必须作为独立后台工作，不阻塞子 Agent；模型选择和额外成本不属于本轮已确认的产品配置。

程序投递报告，不等于主 Agent 已立即读到。主 Agent 的当前模型请求或工具执行有自己的边界，报告需要排队并在可处理的边界进入上下文。报告必须保留其时间和步骤范围，以便主 Agent 识别状态滞后。

主 Agent 收到报告后可以继续自己的工作、查询详情、发出引导或终止子任务，无须对每份报告作显式批准。

## 4. 汇报间隔设置与派发

在子 Agent 设置中增加“汇报间隔（工具调用次数）”。

- 用户填写 N：以用户设置为准，在派发目录和派发结果中向主 Agent 声明生效值。
- 用户留空：表示“由主 Agent 派发时指定”，不表示关闭汇报或无限间隔。
- 用户未设置且主 Agent 派发时也未提供：拒绝启动，返回可纠正的参数错误。
- 生效值必须是正整数；不把 `0`、负数或小数解释成特殊模式。
- 设置来源与本次生效值可在子任务详情中查看。
- 既有定义没有该字段时保持可读取，按照“由主 Agent 派发时指定”处理。

N 是汇报频率，不是执行预算。**达到 N 后汇报并继续，不进入等待审批状态，也不自动终止。**

引导生效后，本段计数重新开始。用户未固定 N 时，主 Agent 可在引导中明确调整后续间隔；未提供新值则沿用本次运行原值。用户已固定的配置不能由主 Agent 的引导悄悄覆盖。

## 5. 引导是一条完整操作

主 Agent 通过一个完整的“引导子任务”操作完成纠偏，不需要分别调用暂停、发送指令和恢复。拟用工具名为 `TaskGuide`，具体契约见实现方案。

```text
主 Agent 发送引导
  → 程序登记引导，关闭后续工具的执行入口
  → 当前已开始的工具正常结束并保存结果
  → 插入引导，重置本段汇报计数
  → 子 Agent 使用原有上下文继续执行
```

必须满足：

1. 若当前工具 A 正在执行，等 A 结束后应用引导。
2. 即使同一条模型回复已计划调用 A、B、C，引导在 A 执行期间到达，也不能继续实际执行 B、C 后才应用。
3. 若当前正在生成模型回复且尚未开始工具，后续工具同样受入口拦截，不能先执行生成出来的旧计划。
4. 保留已经完成的工具结果；未执行的旧计划由接收引导后的子 Agent 重新判断，不能自动重放。
5. 沿用原来的子任务 ID 和上下文，不重新派发，不重做已经完成的操作。
6. 引导生效后自动继续，正常流程不留下一个等待额外“恢复”命令的暂停状态。
7. “引导已接收”和“引导已生效”是两个不同的状态，主 Agent 和界面能够区分。

引导不改变用户目标、权限、模型绑定或已有项目边界；它也不负责回滚已完成操作。

## 6. 本段计数与累计记录

引导真正生效时才重置本段计数，不能在主 Agent 刚发送引导时就重置。引导到达前已经开始、之后才结束的工具，仍归入原执行段。

整个子任务的累计工具次数、模型轮次、耗时、token 使用和审计记录持续累加，不能因引导归零。

达到一个汇报间隔后开启下一批计数；引导生效时关闭原段并开始新段。未达到 N 的剩余记录在引导切换、完成或终止时也应可见，不得丢失。

## 7. 主 Agent 终止与人工终止

保留并完善主 Agent 的 `TaskStop`。在子 Agent 运行卡片和详情页增加独立“终止”按钮。

人工终止通过程序控制接口执行，不转成一句普通聊天消息等待主 Agent 理解。终止只针对选中的子任务，其他子任务和主 Agent 正常工作。

终止行为：

- 立即禁止新的工具调用，取消模型请求并尝试取消在途工具。
- 界面先显示“正在终止”，待操作确实收束后显示“已终止”；无法确认取消的工具要如实显示。
- 保留部分结果、工具记录和终止来源，已完成的文件或外部操作不自动撤销。
- 终止优先于尚未生效的引导，不能因待处理引导而重新启动。
- 向主 Agent 投递明确的终止事件；人工终止不能被当成普通失败而自动重新派发相同意图的任务。
- 对已经结束的子任务重复终止应安全返回当前状态，不影响其他运行。

引导等待当前工具正常结束；终止用于不应继续或无法继续等待的情况。两者共享目标定位和状态管理，但不能混用同一终态。

## 8. 输出上限沿用现状

本轮不新增子任务总步数硬上限，不因达到汇报间隔而停下。输出限制沿用当前子 Agent 的 `maxTokens` 和模型侧已有配置。

**当前 `maxTokens` 限制的是单次模型响应的输出 token，不是整个子任务累计 token、工具次数或总运行时间。** 本轮不改变其含义，也不宣称它能保证子任务在某个累计成本内结束。

引导不会重置已有输出配置或累计用量统计。现有权限、命令执行约束和用户终止能力继续生效。

## 9. 交付边界

本轮目标包括设置与派发声明、自动过程汇报、主 Agent 工具边界引导、人工终止、相应状态展示和记录。第一版继续采用当前主 Agent 与子 Agent 的执行结构，不要求独立子进程隔离、跨应用重启恢复活跃子任务或新增任务总预算。

内置与用户子 Agent 均需要遵守运行时汇报、引导和终止规则；设置入口如何复用现有“复制为我的子 Agent”能力，见实现方案。新增公共接口或持久化字段必须遵守 `AGENTS.md` 的兼容边界，不能借此提升数据库版本、重置数据或削弱权限。

本文是本轮已确认行为的依据。实现方案里的接口名字、模块拆分和摘要算法属于工程建议，可以在不改变以上行为的前提下调整。
