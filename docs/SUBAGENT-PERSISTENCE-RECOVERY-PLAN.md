# 子代理上下文持久化与恢复方案

状态：本轮代码实现已完成；用户明确要求仅实现代码，不执行构建、测试、类型检查或运行服务。故障注入、真实重启及桌面专项验收尚未执行，不能据此宣称已验证可用。自动保存初始关闭，设置页允许显式开启。

关联：[协作实现记录第 13 节](./SUBAGENT-COLLABORATION-IMPLEMENTATION.md#13-完成后召回第一版2026-09-17)、[协作决策记录](./SUBAGENT-COLLABORATION-DECISIONS.md)。

## 1. 目标与推荐范围

补齐 TaskResume 第一版留下的两个缺口：保存可重建的子代理上下文，以及在应用重启、Sidecar 重启、运行实例替换或内存回收后恢复该上下文。

推荐本轮完整交付“正常完成的子代理跨重启召回”。用户继续原会话，主代理通过 TaskList 找到原任务，再显式调用 TaskResume，沿用 delegationId，在保存的上下文中追加新指令，execution 增加一轮。启动、查看历史、打开卡片和加载快照均不得自动请求模型或执行工具。

本轮不实现运行中任务的断点续跑。进程在模型请求、工具调用或新一轮执行期间退出，任务标为 interrupted，保留审计信息，不自动重放，也不退回上一轮 completed 快照冒充当前上下文。后续若需要从中断位置继续，必须另做副作用确认和恢复协议。

首版保持既有语义：失败、人工停止的任务不可召回；TaskGuide 用于正在运行的任务。内存对象被回收不再等于上下文永久丢失，只要磁盘快照仍然有效即可恢复。

## 3. 架构与存储归属

新增桌面主进程服务 `SubagentSnapshotStore`，由它独占快照目录的写入、加密、索引、配额和删除。Sidecar 通过专用内部请求使用该服务，runtime 依赖窄接口 `SubagentPersistencePort`，不直接操作业务目录，不访问 Electron API。

建议新增实现位置：

- `packages/agent-runtime/src/subagent-checkpoint.ts`：快照类型、序列化、验证及版本兼容。
- `packages/agent-runtime/src/subagent-persistence.ts`：存储端口和持久化控制回执类型。
- `apps/desktop/electron/main/runtime/subagent-snapshot-store.ts`：唯一存储实现及串行控制操作。
- 在现有 Sidecar 桥接层增加内部快照请求路由；对 sessionId、调用来源、实例代次和操作类型做校验，不注册为模型工具，不开放给插件或 Renderer 任意文件访问。

建议目录：`<实际业务数据目录>/subagent-contexts/v1/<sessionId>/<delegationId>/`。业务根目录沿用 `PI_DESKTOP_DATA_DIR` 及默认 `~/.pi-desktop`，路径由服务生成，禁止调用方传入任意文件路径。标识符、真实路径、符号链接和读取大小都要验证。

不修改 SQLite schema 18、Rust host protocol 11、原转录格式或已有凭据格式。新增的是本 fork 自有的独立快照格式和桌面—Sidecar 内部能力；双方需做能力检查，旧 Sidecar 不支持时保持仅内存召回，不能假装支持持久化。内部接口的新增仍需在实施时同步维护类型和调用方。

不要将快照写入 scratch；那里会清理，不能承担长期恢复责任。

## 4. 快照需要保存什么

快照只保存可序列化的数据，不保存 Agent 对象、函数、闭包、Promise、AbortController、工具实例或 streamFn。

| 类别 | 建议内容 |
| --- | --- |
| 格式与身份 | formatVersion、contextCodecVersion、sessionId、delegationId、projectRealPath、创建/保存时间、应用内部版本 |
| 执行身份 | execution、executionId、generation、最后正常完成状态、原父轮次/工具调用引用 |
| 模型上下文 | 当前有效 AgentMessage 序列，含当前压缩摘要和保留尾部；多模态附件的可恢复内容或稳定引用 |
| 压缩状态 | checkpointSummary、checkpointTokensBefore、contextCompactions、summaryMessage 的稳定标识；恢复时重建其对象引用 |
| 模型绑定 | 逻辑 provider/model 标识、实际完成本轮的模型、API 类型、规范化端点指纹、thinking 配置、fallback 顺序/位置及失败记录 |
| 执行配置 | 原任务说明、子代理定义摘要/指纹、系统指令指纹、原工具清单及 schema/插件版本指纹、权限上限 |
| 观察与结果 | 累计 turns/toolCalls、reportSeq、segmentId、execution、累计活动时长、最后报告、必要的历史轮次摘要 |
| 用量与审计 | 累计 usage、按 executionId 的本轮用量记录、稳定的结算/事件标识及父轮次归属 |

以下信息不进入快照：API key、Authorization/Cookie 等凭据字段、完整 provider 配置对象、环境变量全集、现有审批令牌、终端/浏览器/SSH 会话句柄。恢复时从当前配置重新获取凭据和工具实现。

采用显式字段白名单和消息 codec，不使用 `JSON.stringify(agent.state)`。区分可恢复的模型消息与只用于展示的消息；未知消息种类或未知 codec 版本必须拒绝恢复，不能丢字段后继续。

完成态要求没有待执行工具调用、未配对工具结果、未应用引导或未完成重试。验证压缩后的有效消息集合；更早工具链可以已由合法摘要替代。不能通过伪造工具结果补齐坏快照。

附件不能引用 scratch 临时路径。必须纳入快照配额并保存内容，或引用具有同等生命周期的受控附件存储；缺失时明确不可恢复。历史工具返回的资源句柄只作历史证据，不代表对应远程会话仍然存在。

## 5. 秘密信息与本地加密

推荐快照正文默认加密保存：由主进程生成随机数据密钥，用操作系统安全存储保护密钥，再使用带完整性认证的加密算法保护快照正文。Electron safeStorage 是候选接入方式，需要新增实现并确认 Windows、macOS、Linux 后端；不把它当作仓库现有能力。Linux 的弱保护后端不得被当作安全密钥存储。

仅对 provider 结构删除 key 不足以防泄露：工具输出、用户输入、模型上下文也可能包含敏感内容。正文及召回指令进入加密载荷；公开头部只包含必要版本、身份和长度，不放报告、提示词和工具参数。日志不输出快照正文。

安全存储不可用时，推荐保留内存召回，标明“持久化不可用”；不静默降级为明文。密钥丢失或快照来自其他系统用户时，返回不可解密，不自动请求模型补全历史。

恢复所需的 provider 专有 reasoning/signature 字段由 codec 按绑定身份验证，不随意跨模型回放；无法确认兼容时拒绝恢复。可以重新解析当前凭据，但不得把签名内容当成通用文本改写。

## 6. 控制状态与原子提交

持久控制记录是召回资格的权威来源，正文快照本身不能决定是否可继续。建议每个任务保留一个原子更新的 control 文件，包含 revision、execution、snapshotGeneration、状态、命令回执和事件待交付信息。敏感字段同样加密。

状态：`running → completed → running`；停止进入 `revoked`，失败进入 `failed`，进程丢失后的 running 进入 `interrupted`。completed 只有指向有效快照时才是 durable-ready；还在内存但保存失败时只允许当前实例内继续。

写入协议：

1. 在目标目录写新的不可变 generation 临时正文，验证、flush 后发布为正式文件。
2. 串行比较 control 的 revision、execution 和实例代次，原子替换 control，使其指向新 generation；这是提交点。
3. 收到存储服务持久化回执后才显示 durable-ready，再异步清理不再引用的旧正文。
4. 原子替换必须采用适用于 Windows 的实现；不能先删除旧 control 再 rename。应专项验证异常退出后的行为，区分进程崩溃保证和断电耐久性。

所有开始、完成、停止、清理通过同一服务串行化，并使用 CAS；不能仅依赖“JavaScript 首个 await 前完成登记”。每个 runtime 获得实例代次，实例替换后旧实例的迟到完成/写入被拒绝。

快照校验和/认证标签只验证载荷完整性，不能替代 session 所属、当前权限和控制状态验证。

## 7. 正常完成与召回流程

### 正常完成

1. Agent idle，所有工具结果已收束，确认本轮正常完成且未被停止。
2. 导出并验证有效上下文，将结果、用量和完成事件的稳定标识一起提交。
3. 通过存储回执确认可恢复，再发布相应恢复状态。结果本身无需因快照失败而改成执行失败。
4. 保存失败时显示 persistence-error，保留当前内存上下文；磁盘状态不得仍宣称上一轮 completed 可用于恢复。

### 显式 TaskResume

1. 从内存任务目录或磁盘轻量目录查找同一会话的 delegationId。保留既有入参 `delegationId / expectedExecution / instruction`。
2. 查控制记录及命令回执，拒绝 revoked、failed、interrupted、旧 execution、无快照或不兼容上下文。重复请求返回原回执，不再执行。
3. 校验当前项目、配置、权限和依赖，加载快照并构造 idle 的 SubagentRun；此时不能调用 prompt/continue/run。
4. 在内存保留并发名额和任务锁，通过持久控制 CAS 记录新 execution、命令 ID、running 状态及当前实例代次。请求身份建议使用 sessionId + parentTurnId + toolCallId，并保存参数摘要，拒绝同 ID 不同参数。
5. 持久化成功后才追加 instruction 并执行。返回快速接收回执，不等待模型完成；失败则释放预留名额，不发起执行。
6. 后续 TaskWait、TaskGuide、TaskInspect 和报告事件沿用现有机制；新轮次绑定当前父轮次，历史记录保持原归属。

内存召回与磁盘恢复走同一持久控制门，避免内存路径绕过命令去重和停止标记。冷启动读取目录不占用模型执行名额；真正执行时才占用。

新一轮开始回执已经持久化、但调用模型之前崩溃，也按 interrupted 处理。首版接受“可能少执行一次”，不冒险自动重放一次。

## 8. 停止、崩溃和用量结算

用户停止先立即取消本地工作，同时提交持久 revoked 标记；只有收到回执才能宣称跨重启撤销已生效。停止必须支持只有磁盘上下文、没有活跃 runtime 的任务。

停止持久化失败时，本地保持停止并提示失败，不返回完整成功。当前存储服务封闭该任务及受影响会话的恢复入口并重试。应用/Sidecar 启动与退出记录脏运行标记；未干净退出的所有者涉及的会话默认隔离，避免丢失停止回执后旧 completed 快照重新开放。无法可靠核清时保持不可恢复，不能按“最新正文还在”放行。

| 故障点 | 重启后的行为 |
| --- | --- |
| 写正文时中断，control 尚未提交 | 临时/孤儿正文不使用；以 control 为准 |
| 新正文已保存，control 更新失败 | 不显示新快照可恢复，不退回较旧 execution |
| running 已提交，模型/工具执行期间崩溃 | 标为 interrupted；不恢复上一轮、不重放工具 |
| 完成状态已提交，UI/转录尚未收到事件 | 按稳定事件 ID 补投结果/审计，不执行任务 |
| 停止与完成保存并发 | revoked 优先；迟到完成不能重新开放召回 |
| 快照损坏、认证失败、版本过新 | 隔离并显示原因，不尝试截断解析 |
| 存储空间不足或系统密钥不可用 | 结果可查看；仅内存召回或明确不可恢复 |

用量分为原 execution 累计账本和当前父轮次新增用量。恢复目录、加载快照、补投事件不能把历史 usage 再加到当前 turnSubagentUsage。新 execution 只累计本轮新增用量。

控制记录保留待交付的完成事件，使用稳定 `sessionId/delegationId/executionId/eventKind` 标识重试。沿用已有持久化消息 ID 做幂等补投；若当前事件通路缺乏完成回执，需要新增内部确认或查询，不得把 `onEvent` 返回当作落盘确认。

转录和快照是两个存储域，不假设跨文件/数据库原子事务。实施时必须建立“control 中的待交付事件 → 原持久化通道 → 确认”的收敛路径。崩溃时提供商已计费但本地未收到 usage 的部分只报告未知，不能声称账本覆盖了所有实际费用。

## 9. 恢复时的兼容与权限

恢复总是验证会话仍存在、属于当前业务目录且项目真实路径匹配。不能按磁盘文件存在直接恢复被删除的会话。

| 变化 | 推荐策略 |
| --- | --- |
| 凭据轮换，逻辑 provider/端点/模型不变 | 从当前配置读取新凭据，不使用旧快照凭据 |
| 原模型不可用或实际 fallback 模型失效 | 标为 blocked，不自动切换其他模型冒充原上下文 |
| 仅父代理模型变化，子代理有效绑定不变 | 重新校验子代理自身绑定后可恢复 |
| 子代理定义、系统指令、工具 schema 或插件实现发生不兼容变化 | 标为 blocked；首版保守匹配，不自动迁移执行语义 |
| 权限扩大 | 仍受原权限上限约束，旧审批不复用 |
| 权限收紧或工具被禁用 | 当前策略优先；若所需工具不再可用则阻止恢复，不静默补权限 |
| 工作区文件正常变化 | 不要求工作区内容哈希完全相同；追加“已从快照恢复，请重新读取将修改的文件”等状态说明 |
| 浏览器/SSH/终端等资源重启失效 | 不恢复旧句柄；后续按当前工具流程重新连接，沿用审批 |

建议有效权限取原任务上限与当前会话策略的交集。项目、插件信任、路径权限和扩展技能只读限制都需要重新建立，不缓存之前的许可结果。

共用业务目录的旧版本不认识快照撤销记录，因此不能保证它在运行/停止任务后仍与新恢复目录一致。兼容策略应做到：旧版本可忽略独立目录继续读取原业务数据；新版遇到无法归属到支持快照协议的会话轮次、转录修订或删除证据时，保守阻止受影响会话恢复。具体用现有轮次/转录标识加本服务覆盖水位实现，需验证这些标识能覆盖相关变更；不能只看文件修改时间，也不能宣称能识别任意历史程序的操作。

## 10. 查询、界面与保留策略

保留 canResume 布尔字段，但新增恢复来源、持久化状态和不可用原因。状态查询只读取受限元数据，不创建 Agent、不连接提供商。

| 展示状态 | 含义 |
| --- | --- |
| 可召回 · 内存 | 当前实例上下文有效，但可能尚未保存成功 |
| 可召回 · 已保存 | 快照及当前绑定校验通过，可按需加载 |
| 正在保存 | 本轮已完成，持久化尚未确认 |
| 待校验 / 配置不兼容 | 尚未拿到当前配置或依赖校验未通过；不能显示可召回 |
| 已停止 / 执行中断 / 快照不可用 | 明确说明阻止原因 |
| 已清理 | 正文已过期或因配额删除，历史结果仍可查看 |

TaskList 合并内存与磁盘轻量目录并按 delegationId 去重；列表有界，需要时分页。TaskInspect 展示恢复原因和快照版本，不返回秘密正文。TaskWait 查询旧 completed 任务只返回结果，不重新推送一次“刚完成”消息。

保留现有内存 100 条上限。磁盘推荐每会话最多 100 份最新完成态上下文、全局正文配额 512 MiB、默认保留 30 天；单份上限建议 16 MiB。以上是待确认初值，应包含附件、加密开销及临时写入空间。超限不能截断上下文后仍标可恢复。

正常情况下每任务只保留当前 control 指向的完成态正文，旧 generation 在新版本成功提交后删除。清理正文不得删除仍需阻止重放的 revoked、interrupted、命令去重和 execution 水位记录；这些小型控制记录保留到会话删除，超出资源限制时停止新增持久化并提示，不能通过丢弃安全记录腾空间。

会话删除采用“封闭写入口及提升代次 → 停止/释放实例 → 删除会话 → 清理快照”顺序。删除失败时保持封闭直到核清结果，不能让迟到写入重建快照。启动时利用权威会话列表清理孤儿目录，覆盖旧版本删除会话、主进程崩溃或绕过桌面删除入口的情况。

## 11. 实施顺序

1. **状态模型和 codec**：定义快照白名单、控制状态机、兼容规则和错误码；SubagentRun / Observer 增加纯导出/恢复入口，恢复不执行模型。先解决摘要对象引用、工具配对和附件生命周期。
2. **存储与内部桥接**：实现主进程单写服务、加密、原子 generation/control 提交、CAS、运行代次、脏运行隔离及配额；接入业务根目录和会话存在性查询。
3. **执行生命周期**：完成时提交快照；TaskResume 持久化接收后执行；TaskStop 持久撤销；明确 dispose、用户停止、实例替换和内存回收的不同含义。补齐事件回执与用量幂等收敛。
4. **冷恢复与界面**：Sidecar 新实例读取目录，按需构造原任务；扩展 TaskList/Inspect、只读 recall IPC 和卡片状态；完成停止/删除仅磁盘任务的路径。
5. **专项验收**：完成下节故障注入与重启测试后，再启用默认持久化。期间不修改或伪迁移既有历史任务，升级前无快照的任务保持原能力边界。

这些步骤存在依赖，不能在状态和存储协议尚未稳定时并行改写召回/停止路径。稳定后可独立推进 UI 状态展示和 codec 专项测试。

## 12. 验收标准与验证范围

实施时只验证本功能及直接相关路径，使用临时独立业务目录、假模型和受控工具；不默认运行全量测试或启动后端。真实桌面验证需按要求使用可见终端。

必须通过的场景：

- 完成 → 保存 → 销毁 runtime/重启 Sidecar → 原会话 TaskList → TaskResume；ID 不变，execution 增加，历史上下文可见。
- 完整应用重启后恢复，包括加密密钥、主进程服务、目录查询和卡片状态；只重建内存对象的单测不能替代此项。
- 压缩过、多模态、fallback 后完成的任务恢复；计数、报告序号、累计用量连续，idle 等待不请求模型。
- 恢复不得重放历史工具；用可计数的副作用工具断言旧执行次数不增加。
- 重复召回、同命令不同参数、旧 expectedExecution、并发满额、停止与完成竞态、旧 runtime 迟到回调。
- 在正文写入、control 提交、开始执行、完成事件补投、停止撤销各窗口注入进程退出，验证不重复执行、不复活已停止任务。
- 保存失败、坏正文、未知版本、密钥缺失、工具结果缺失、附件丢失、权限变更和模型失效均有明确状态。
- 内存淘汰后仍可冷恢复；正文配额清理后不可恢复但结果仍可查；控制撤销记录不被误清理。
- 会话删除与保存并发、删除后重新启动、旧版本修改/删除共用会话，均不产生可执行的孤儿快照。
- 旧执行结算/审计重投幂等；当前父轮次只统计新用量，不把历史用量重复计入。

实施完成后再更新原实现记录第 13.4 节的缺口状态，并明确实际通过的验证与剩余限制。

- `subagent-checkpoint.ts`、`subagent.ts`、`subagent-observer.ts`：有效消息白名单、绑定指纹、摘要引用和观察状态的导出与 idle 恢复。
- `subagent-persistence.ts`、`subagent-persistence-client.ts`：版本化内部端口、执行 CAS、撤销回执及 Sidecar 能力探测。

## 13. 建议确认的产品取舍

推荐一次性确认以下组合，再进入实现：

1. 本轮支持正常完成后的跨重启召回；运行中崩溃仅标 interrupted，不做断点续跑。
2. 默认自动保存完成态，只有明确 TaskResume 才执行；采用本地加密，系统安全存储不可用时仅保留内存能力。
3. 采用 30 天 / 512 MiB 全局正文配额 / 每会话 100 份 / 单份 16 MiB 的初值，并提供关闭保存、清理快照和状态说明。
4. 配置不兼容、旧版本介入无法确认或异常退出涉及停止状态不明时，保守阻止恢复，保留历史结果供重新判断。

该组合优先让“做完的子代理关软件后还能叫回来”稳定可用。运行中故障的自动续跑、跨设备迁移和跨模型上下文迁移留待后续独立设计。
