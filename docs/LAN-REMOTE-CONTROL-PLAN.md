# 局域网远程控制插件实施计划

状态：待实施。已创建功能分支，本计划已按用户确认调整为插件优先方案；尚未实现插件或修改宿主功能。

- 功能分支：`feat/lan-remote-control`
- 起点提交：`5e10c80a`
- 目标：安装并开启功能插件后，桌面生成局域网链接和二维码，手机或其他局域网设备通过浏览器访问项目、会话并操作电脑上的智能体。
- 技术方向：遵循上游现有插件开发机制，优先纯插件实现；只有经核实的接口缺口才考虑补充宿主受控能力。
- 交付方式：分为“第一版：日常可用”和“进阶版：完善交互”，以功能闭环和验收结果衡量进度，不设人天估时。

## 1. 产品与兼容边界

电脑上的宿主是唯一的数据与执行中心。插件和浏览器不另开业务数据库、不保存模型凭据、不另起智能体运行环境；复用现有 Host、Sidecar、会话和权限策略。

功能以可安装、启用、禁用和卸载的插件交付。网络服务、移动网页、连接管理和配置界面由插件承载，不默认把专用设置页、HTTP 服务或 Web 构建目标加入桌面主应用。未安装或未启用插件时，不启动远程服务。

桌面应用和插件必须运行且网络可达。应用退出、休眠、插件停用或关闭远程访问后，浏览器显示明确的断线状态。局域网模式不依赖云服务，不包含公网中继、端口映射或互联网账号体系。

沿用“这是一个助手 / this-is-a-agent”的品牌和本项目的主题、配色、字体、图标与消息风格。参考截图用于确定交互能力，不复制其品牌和皮肤。插件在构建时复用适合共享的 UI 与样式，产物自包含，不在运行时引用桌面源码或开发服务器。

继续使用既有 `~/.pi-desktop` 或 `PI_DESKTOP_DATA_DIR`。保持数据库、凭据格式、内部包名、原有协议及业务目录互斥机制；插件不直接读写宿主数据库或转录文件。本功能默认不需要数据库迁移。公共接口、数据格式或现有权限语义需要调整时，先说明具体影响并确认；本计划不构成绕过这些边界的授权。

插件声明自己的版本和最低宿主版本。优先使用上游现有 API；如果最终依赖本 fork 新增接口，必须明确要求支持该能力的宿主，不宣称上游原版也能完整运行。启动时检测实际能力，不仅比较版本字符串。

| --- | --- |
| 插件入口、服务与界面 | 已有独立 Node 入口、生命周期、常驻服务、设置和面板机制，可用于插件后台与桌面管理页 |

第一项实施工作是形成实际能力矩阵：操作/事件、所需权限、参数与返回字段、生命周期、是否需要桌面确认、缺口和降级表现。禁止因为 SDK 没有专门命名的方法就认定能力不存在，也禁止把文档中的设计视为已经实现。

## 3. 实现结构与职责

```text
手机 / 平板 / 其他电脑浏览器
  └─ 插件自带移动网页：项目 → 会话 → 对话
            │ HTTP 静态资源 + 已鉴权 WebSocket
远程控制插件（独立插件进程）
  ├─ 网络服务、配对、设备授权、撤销与请求白名单
  ├─ 移动网页、连接状态、重连与消息去重
  ├─ 插件设置/面板：开关、地址、二维码、设备管理
  └─ 宿主适配器：现有 desktop.control + 可用事件
            │ 现有插件权限网关
桌面宿主
  ├─ 项目、会话、模型、工具、队列、审批及持久化
  ├─ 桌面界面与既有事件流
  └─ 仅在确认缺口后补充受控事件/授权等能力
```

### 3.1 插件内部结构

- 插件 manifest 按实际需求声明权限、服务和界面贡献；不申请与功能无关的文件、进程或凭据权限。
- 桌面管理面板通过现有插件 UI bridge 调用插件入口；移动网页通过鉴权后的 HTTP/WebSocket 访问插件。二者不是同一个信任边界。
- 插件宿主适配器调用 `pi.desktop.invoke` 等已授权 API，不直接调用桌面 IPC，不伪造 Electron sender，不读取内部数据库。
- 对浏览器仅暴露必要的业务操作白名单，参数校验与输出字段过滤独立执行。不能把整个 `desktop.invoke`、操作枚举或任意 IPC channel 原样转发到网络。
- 手机浏览项目、切换会话属于设备本地导航，不调用会改变桌面当前项目/会话的操作。创建、发送等操作明确携带目标会话/项目；如果现有 API 依赖当前桌面状态，记录为能力缺口。
- 请求带关联 requestId，变更操作另带幂等标识；事件明确会话、作用域和顺序信息。远程协议独立协商，不为此提升 Host protocol。
- UI 优先复用纯组件、主题变量、Markdown 与代码展示；不能通过复制整个桌面 App 或引入 Electron 依赖实现复用。必要时提取小范围共享模块，不预设全面重构 `api.ts` 或 app store。

### 3.2 宿主最小补齐原则

只有能力矩阵证明缺口后才增加宿主代码，并单独说明原因和接口范围：

1. 优先补插件可安全订阅的会话事件、状态快照与取消订阅机制，范围由授权约束，不输出凭据或无关内部数据。
2. 配置模型、手机审批等遇到原生确认限制时，不能把 `dangerous` 改成普通操作或自动代点确认。若需要一次桌面授权后的远程审批能力，设计独立、可撤销、范围明确的授权，并在改动公共接口/权限语义前确认。
3. 优先增加可复用、可能力检测的插件 API，不把插件的二维码、网页路由或设备 UI 塞进宿主核心。
4. 不默认修改 preload、桌面设置导航、数据库或构建主入口；仅在共享组件或已确认接口补齐确有需要时调整相关代码。

纯插件可先交付已支持能力，但不把轮询历史消息称为完整实时流，也不把“手机提交审批后仍需电脑确认”称为手机独立审批完成。无法达到第一版目标的缺口必须明确记录，不能静默缩减范围。

### 3.3 授权与网络边界

- 默认不监听网络；由桌面插件面板主动开启。显示可用局域网地址，多网卡可选择，不能把 localhost 当成手机可访问地址。
- 新设备使用短期、一次性配对凭证并经桌面确认。确认只能来自可信的本地插件面板/宿主渠道，远程端不能调用配对批准接口。
- 二维码不携带长期凭据；短期配对信息若放 URL，使用 fragment，交换后清理地址且不写日志。
- 第一版授权仅在本次插件服务运行期间有效，不新增宿主持久化凭据格式。关闭、停用、重载、卸载、崩溃或应用退出均使授权失效；配对码过期与已授权连接失效分别说明。
- 静态页面可公开加载；项目、会话、附件及事件必须鉴权。HTTP/WS 分别执行适用的 Host/Origin、授权及输入校验，拒绝未知来源，不启用宽泛 CORS，防范跨站请求与 DNS rebinding。
- 增加配对尝试、连接数、消息大小及请求速率限制。网络可达不代表已获访问权限。
- 不返回 API key、token、密码或完整提供商配置，不提供任意文件读写、shell、数据库管理、原生窗口控制。工具仍由宿主按原有策略执行。
- 第一版限定可信局域网：HTTP/WS 不提供传输保密，面板应说明；公网与 HTTPS 证书部署不在两阶段范围内。
- 不自动修改防火墙或路由器；不可达时提供地址、监听及网络隔离提示。

### 3.4 生命周期与多端一致性

- 通过插件现有服务和生命周期机制管理网络服务。停止操作幂等：关闭监听、断开客户端、取消订阅、清理心跳/计时器、清空内存授权与请求记录。
- 禁用、重载、卸载和异常退出不能留下独立后台服务或占用端口；不启动脱离插件进程的守护进程。
- 关闭插件只终止远程访问，不默认停止已经由宿主接收的智能体任务，不删除会话与业务附件。卸载只按平台规则处理插件自身资源。
- 宿主是消息、状态、队列和审批的权威来源。插件做请求去重与结果关联，不另造执行队列或持久化优先顺序。
- 断线后先核实提交结果，不盲目重发；结果无法确定时明确提示，跨插件/应用重启不自动重放变更请求。
- 同一审批仅允许一次有效决议，其他端同步为已处理；原生确认仍按当前宿主规则执行。
- 事件订阅按设备授权过滤。重连时协调快照与增量，避免订阅空窗；优先复用已有转录合并语义，以宿主最新状态恢复无法补发的流式片段。
- 支持心跳、退避重连、页面切后台后的恢复；设备导航互不抢占。

## 4. 第一版：日常可用

### 4.1 插件安装与桌面管理

通过上游现有插件安装流程加载插件包，管理入口使用插件设置/面板贡献：

- 服务开关、地址与端口、复制链接、二维码。
- 配对有效期、新设备确认、已连接设备、单设备撤销和全部断开。
- 启动失败、端口占用、缺权限、宿主能力不足、无可用地址等状态。
- 禁用/重载/卸载的完整资源清理；不默认增加桌面原生设置 tab。

### 4.2 浏览器功能

- 配对页、连接状态、授权失效与宿主不兼容提示。
- 已有项目列表、搜索/最近访问、项目内会话列表和运行状态。
- 在已有项目创建新会话，进入历史会话；不从手机选择电脑任意目录创建项目。
- 发送消息、真实流式回复、Markdown/代码块、工具执行和结果展示、停止生成。
- 运行中发送遵守现有普通队列语义，第一版不增加高级队列操作界面。
- 权限审批与智能体提问、多端已处理状态；现有网关需要桌面确认时明确提示。手机独立处理的授权缺口必须解决或明确标为未完成。
- 选择现有可用模型，遵守模型绑定、插件提供商与能力限制，不管理凭据；现有会话配置需要原生确认的问题纳入接口评估。
- 桌面和手机同步消息与状态，刷新、断网、切后台后恢复。
- 手机单栏导航、宽屏侧栏，适配触摸、软键盘、安全区、长消息和横向代码滚动。

### 4.3 实施顺序

1. **核查能力与插件骨架**：依据官方指导和当前 devkit 创建 manifest/入口/面板骨架，形成操作、事件和权限矩阵；先确认实时同步、审批、模型配置及后台服务能力。
2. **插件服务与授权**：在插件进程实现静态服务、HTTP/WS、配对、设备管理、请求白名单和生命周期；先完成未授权拒绝路径。
3. **移动端浏览闭环**：插件独立 Web 入口、主题、项目与会话导航，通过宿主适配器读取历史数据。
4. **会话操作与缺口处理**：接入创建、发送、停止、模型、审批与提问；必要的宿主补齐单独设计并遵守确认边界，避免先大面积修改主应用。
5. **实时同步与恢复**：接入可用事件、快照、幂等及审批竞争处理，完成多端和后台恢复。
6. **插件打包与界面收口**：完善二维码、设备管理及移动交互，通过 devkit 生成包含后台、面板和移动静态资源的安装包，声明兼容范围。

### 4.4 完成标准

- 插件可按既有流程安装、启用和停用，无需开发服务器；未开启时不监听局域网端口。
- 同局域网第二台真实设备扫码并获授权后可查看项目、新建/进入会话、发送消息并接收真实流式回复。
- 桌面和手机的消息、工具状态、停止结果与审批决议一致；互不抢占导航。
- 重复请求不重复执行，运行中发送沿用宿主队列规则。
- 手机断网/刷新后恢复持久化消息和待处理状态，不重复发送或复活历史审批。
- 手机独立审批与模型选择如仍依赖桌面逐次确认，必须列为明确限制，不能把对应目标标为完成；不得以降低权限检查达成验收。
- 未授权、配对过期、错误 Origin/Host、非法参数和已撤销设备均被拒绝。
- 停用、重载、卸载、异常退出及宿主退出不残留端口、授权和订阅；宿主已接收的任务与会话保留。
- 手机无法读取凭据或任意本地文件；桌面既有权限、模型绑定和数据兼容性保持。
- 安装包自包含，最低宿主版本及能力缺失提示准确，窄屏输入与滚动正常。

## 5. 进阶版：完善交互

继续扩展同一个插件，复用第一版授权、宿主适配和同步机制。

### 5.1 功能范围

- **命令与技能**：现有斜杠命令、技能和子智能体选择，按能力展示；桌面专属操作明确禁用，linked 技能继续只读。
- **附件**：手机选择/拍摄图片与上传文件、预览、移除、重试。限制类型/大小，服务端生成标识，在插件受控暂存区域接收，再通过合法宿主接口挂接消息；缺少附件交接 API 时先记录缺口。禁止靠直接改业务文件或接受绝对路径完成导入，预览和下载同样鉴权。
- **消息操作**：编辑、重试、复制等沿用既有语义和运行/队列锁定规则。
- **优先队列**：展示、移动、编辑与“立即发送”，沿用持久化优先组和平稳停止当前轮后执行的语义，不恢复旧 steering 行为。
- **模型选项**：思考强度等会话级能力及生效状态，不扩展为远程凭据或全局提供商管理。
- **引用、批注与侧边对话**：复用宿主既有数据与关联，通过受控接口操作，以底部面板或独立页面适配手机；不直接修改持久化文件。
- **体验完善**：长会话加载、搜索、阅读位置、连接质量、多设备管理和可用主题呈现。

### 5.2 顺序与完成标准

1. 命令/技能和模型选项：手机与桌面生效一致，不绕过能力限制。
2. 附件：上传至消息引用形成闭环，非法路径、越权读取和超限上传被拒绝；清理不误删已有业务附件。
3. 消息与队列：并发操作后顺序一致，锁定优先组不能被违规编辑或移动。
4. 引用、批注和侧边对话：关联完整，可在手机创建/查看并返回主会话，桌面展示不退化。
5. 移动体验：软键盘、不同屏幕、长内容和断线状态下入口可用，没有只靠 hover 才能触发的操作。

每项进阶能力先核查宿主接口；插件 API 的存在不能从桌面 UI 已有该功能推导出来。缺口按第 3.2 节处理。

下列是实施后的验收要求，不表示已经验证。遵守仓库默认不运行测试、全量构建或服务的约定；用户要求验证时只覆盖相关范围并记录真实结果。
